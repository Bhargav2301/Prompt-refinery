# Existing usage writer contract — PA-001

Local hardening of existing operational records, 2026-10-18. Runtime contract: `src/lib/server/usage-telemetry-schema.ts`. This is not the future optional behavioral event dictionary, a consent grant, or a new ingestion endpoint.

| Fields | Runtime behavior |
| --- | --- |
| Root `requestId` | UUID generated by existing server callers; invalid value skips write |
| `tenantId`, `workspaceId`, `principalId`; legacy UID path | 1–200 ASCII letters/digits/underscore/hyphen; invalid value skips write; authenticated caller remains responsible for ownership |
| `task`, `inferenceMode`, root `status`, `source`; legacy `kind`, `success` | Explicit existing enums/boolean; invalid required values skip write. Legacy source/success default to app/true only when omitted |
| Root `creditsCharged`, `latencyMs` | Nonnegative safe integers, required; invalid values skip write |
| Optional token counts/item count | Nonnegative safe integers or null; malformed values become null |
| Provider cost, attempt cost | Finite nonnegative number up to `Number.MAX_SAFE_INTEGER` or null; valid fractional costs retained |
| Provider/quality/fallback/technique | Explicit category allowlists; unknown or malformed values become null |
| Model | Explicit reviewed identifiers matching current source defaults; custom/unknown names become null even if they resemble a model identifier. Numeric costs remain available |
| Error code | Explicit known names or exactly `ProviderHttp400`–`ProviderHttp599`; unknown nonempty values → `UnknownError`; absent/empty → null |
| Attempts | Inspect first three entries; discard malformed entries; project each entry's allowed fields; valid HTTP status range 100–599 |
| Legacy score/itemCount | Finite score clamped to 0–100, otherwise null; finite nonnegative itemCount floored/clamped to 1–100, otherwise 1 |
| Timestamps | Generated by writer; input cannot override them; existing expiry calculations unchanged |
| Any unknown property | Discarded at top level and inside attempts; never forwarded or logged |

Examples: `errorCode: 'ProviderTimeoutError'` is retained. A private sentence in `errorCode` becomes `UnknownError`. A URL in `model` becomes null. `{ prompt: 'synthetic private content' }` added to an otherwise valid internal event is ignored. An unknown task or URL in a subject ID skips storage entirely. No regex-based “redaction” is used to preserve arbitrary diagnostic text.

Both the stored event and the daily numeric increments are derived from the same parsed projection. Malformed optional metadata cannot create NaN/Infinity/negative counters. No consent decision or tenant authorization can be inferred from schema validity.

Adding a category requires code review, synthetic tests and a documented purpose. Do not automatically add runtime environment strings or provider-returned values to the allowlist. Future public optional ingestion must separately reject unknown fields and enforce current consent, rate limits, payload size, deduplication and a server-side collection switch.

## Legacy migration follow-up — PA-003

`legacy-usage-migration.ts` applies the legacy user-event schema plus a required Firestore Timestamp. Unknown fields are stripped; optional string categories are sanitized by the same allowlists. Tenant/workspace/creator come only from authenticated migration context. No raw legacy document ID/path, old actor fields or source provenance text is retained in the destination; the existing deterministic SHA-256-derived document ID remains for idempotent retries.

Future, missing/invalid-date, already-expired and invalid-core events are skipped. Expiry is the earlier of original creation + 90 days and a valid earlier source expiry. Migration never resets the event date. Valid records use replacement (`merge: false`) writes so a partial old destination's unknown fields cannot survive. Usage migration counts now mean eligible records. Dry runs perform no writes and report eligibility. No usage aggregate counters are incremented.

Migration version stays 2: completed users are not automatically remigrated. Existing source records and skipped/already-migrated destinations are not cleaned or deleted. This is a prevention patch, not historical erasure or verified TTL execution.
